# Saathi backend

FastAPI service for the Saathi web app and WhatsApp channel. See [../README.md](../README.md) for
running the whole app and [../docs/architecture.md](../docs/architecture.md) for the design.

## How a chat turn works

```
message ─► redact IDs (Aadhaar, PAN, phone, account numbers)
        ─► LLM extracts profile facts (age, occupation, income, ...)
        ─► rules engine evaluates every active scheme ─► eligible / not eligible / needs info
             ├── needs info ─► ask the one question that settles the most schemes
             └── decided    ─► list eligible schemes, documents, how to apply
        ─► LLM phrases the reply in the user's language and script
```

The LLM **never decides eligibility**. Rules do, so a verdict is reproducible and can be traced
to a rule.

## LLM providers

All model calls go through `agents_core.llm.LLMProvider` (in [`libs/agents-core`](../../../libs/agents-core)).
The workspace default comes from `LLM_PROVIDER`; `SAATHI_LLM_PROVIDER` overrides it for Saathi.

| Value | Backend | Auth |
|---|---|---|
| `azure_openai` | Azure OpenAI deployment | API key, or Microsoft Entra ID when no key is set |
| `gemini` | Gemini via Google AI Studio or Vertex AI | API key, or application default credentials with `GEMINI_USE_VERTEX=true` |
| `openai_compatible` | OpenAI, Ollama, vLLM, LM Studio, ... | API key / base URL |

Without a provider the web app still runs; only chat returns 503.

## CLI

```bash
saathi chat --show-profile            # terminal chat using the YAML schemes; stores nothing
saathi validate                       # check data/schemes/*.yaml
saathi seed                           # add new YAML schemes to the database (never overwrites)
saathi users set-role <email|phone> <citizen|helper|admin>
saathi serve                          # API on 127.0.0.1:8000
```

## Database migrations

From the workspace root (so the root `.env` is read):

```bash
alembic -c apps/saathi/backend/alembic.ini upgrade head
alembic -c apps/saathi/backend/alembic.ini revision --autogenerate -m "describe change"  # after editing db/models.py
alembic -c apps/saathi/backend/alembic.ini check    # fails if models and migrations differ
```

Review every autogenerated migration before committing it. For example, Alembic emits duplicate
CHECK constraints for `Enum(create_constraint=True)` columns; delete the extra `sa.CheckConstraint` lines.

## Scheme data

The database is the source of truth; admins edit schemes in the web UI, and every edit creates a
revision and sends the scheme back to draft. The YAML files in `data/schemes/` are seed data for
new installs:

```yaml
id: atal-pension-yojana
name: Atal Pension Yojana (APY)
level: central            # or: state  (then also set state: bihar)
eligibility:              # every rule must hold
  - field: age
    op: gte               # eq ne in not_in gte gt lte lt
    value: 18
    reason: Must be at least 18 years old
  - any:                  # at least one sub-rule must hold
      - {field: social_category, op: in, value: [sc, st], reason: SC or ST}
      - {field: gender, op: eq, value: female, reason: Woman}
    reason: Must be SC, ST or a woman
documents: [...]
notes:                    # conditions the rules cannot check; shown to people and to the agent
  - One member per family.
how_to_apply: ...
source_url: https://...   # the official page you checked
verified_on: null         # a date here seeds the scheme as verified
```

Rule fields must be fields of `UserProfile` (`src/saathi/profile.py`). To support a new fact, add a
field there with a `question`; the web profile form picks it up automatically.

## WhatsApp

Set the four `SAATHI_WHATSAPP_*` values and an LLM provider, then register
`https://<your-host>/webhooks/whatsapp` in the Meta app. Every webhook POST is checked against
Meta's `X-Hub-Signature-256` HMAC. A WhatsApp number shares one account and citizen record with a
web sign-in on the same number (`services/whatsapp.py`), consent is asked over WhatsApp, voice
notes go through the configured `SPEECH_PROVIDER`, and "LOGIN <code>" messages complete
"Sign in with WhatsApp" (`auth/whatsapp_login.py`). Voice notes need `ffmpeg` (included in the image).

## Tests

`pytest` (from the workspace root, or `pytest apps/saathi/backend`). The API tests run against
SQLite in memory with a scripted LLM and a captured SMS sender; the migration is checked
separately against PostgreSQL with `alembic check`.
